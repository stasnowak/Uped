# Uped upload/download path — technical research (2026-10-07)

Scope: Go static binary, net/http + embed.FS, vanilla JS, plain HTTP/1.1 on a LAN, no auth. Facts below were checked against primary sources where the egress proxy allowed; items marked **[unverified]** come from search snippets only (developer.chrome.com, bugs.webkit.org, go.dev, MDN, WHATWG, w3.org, web.dev, caniuse.com were all blocked).

## 1. Chunked resumable uploads

**tus protocol (1.0.0, 2016)** — HEAD → `Upload-Offset`; PATCH with `Content-Type: application/offset+octet-stream` + `Upload-Offset`, server replies 204 with new offset, **409 on offset mismatch**; creation ext = POST with `Upload-Length`/`Upload-Metadata` (base64 k/v) → `Location`; checksum, expiration (`Upload-Expires`), termination (DELETE) extensions. One PATCH may carry the whole file or a chunk; the server keeps whatever bytes arrived, so resume is byte-granular even without client chunking. [protocol.md](https://github.com/tus/tus-resumable-upload-protocol/blob/main/protocol.md)

**tusd handler** — `github.com/tus/tusd/v2/pkg/handler`, v2.10.1 (2026-09-14). `pkg/handler` imports std lib + `golang.org/x/exp/slog`; `pkg/filestore` writes `[id]` + `[id].info` (JSON) and needs a locker. But the module's go.mod (go 1.25.14) requires ~30 modules (AWS/GCS/Azure SDKs, grpc, prometheus, zerolog...). Module graph pruning means only imported packages compile, but go.sum balloons and you inherit tusd's upgrade cadence. `Config.EnableExperimentalProtocol` adds the IETF draft. [pkg/handler](https://pkg.go.dev/github.com/tus/tusd/v2/pkg/handler) · [imports](https://pkg.go.dev/github.com/tus/tusd/v2/pkg/handler?tab=imports) · [go.mod](https://github.com/tus/tusd/blob/main/go.mod)

**tus-js-client** — `dist/tus.min.js` ≈65 KiB (18 KiB gz), zero deps, needs only XHR2/File/Blob/Web Storage, usable from a `<script>` tag (no build step). Defaults: `chunkSize: Infinity` ("Do not set this value, unless you are being forced to"; "<a few MBs may reduce the upload performance dramatically"), `parallelUploads: 1` (>1 needs the concatenation ext), `retryDelays: [0,1000,3000,5000]`, `storeFingerprintForResuming: true`. Browser fingerprint = `["tus-br", name, type, size, lastModified, endpoint].join("-")`. After a reload the page cannot re-open the File: the app calls `findPreviousUploads()` once the user re-selects the file, then `resumeFromPreviousUpload()`. [installation](https://github.com/tus/tus-js-client/blob/main/docs/installation.md) · [api](https://github.com/tus/tus-js-client/blob/main/docs/api.md) · [fileSignature.ts](https://github.com/tus/tus-js-client/blob/main/lib/browser/fileSignature.ts)

**IETF resumable upload** — still `draft-ietf-httpbis-resumable-upload-12` (July 2026, expires 2027-01-07), not an RFC. iOS 17+ URLSession implements a frozen draft-03 (native apps only, not Safari pages; developers report it hangs after the `104` interim response). [datatracker](https://datatracker.ietf.org/doc/html/draft-ietf-httpbis-resumable-upload/) · [Apple forum 818379](https://developer.apple.com/forums/thread/818379)

**fetch() streaming request bodies** — Chromium 105+, requires `duplex: 'half'`, and "the fetch will be rejected if the connection is HTTP/1.x" (HTTP/2 only); Firefox buffers the full body; Safari only got "initial support" in Safari Technology Preview 250. On plain HTTP/1.1 this is unusable — confirmed. Use `XMLHttpRequest` with `xhr.upload.onprogress` (`loaded/total` per request) and `xhr.send(file.slice(a, b))`. **[page blocked; from Chrome article snippet]** [Chrome article](https://developer.chrome.com/docs/capabilities/web-apis/fetch-streaming-requests) · [STP 250](https://webkit.org/blog/18191/release-notes-for-safari-technology-preview-250/)

**Blob.slice is lazy** — File API: `slice()` "returns a new Blob object with bytes ranging from start to end" referencing the original, no copy. A File carries a *snapshot state*; if the on-disk file changed/vanished, reads throw `NotReadableError` (this is why a restored iOS tab can hold an unreadable File). `lastModified` = ms since epoch from the filesystem. [FileAPI source](https://github.com/w3c/FileAPI/blob/main/index.bs)

**Chunk size** — tusd/tus guidance and vendor write-ups converge on 5–16 MB; the only hard numbers are tus-js-client's warnings above. On a LAN, 16 MiB gives ~1 request/s at 100–150 Mbit/s Wi-Fi and bounds re-upload after a drop to ≤16 MiB. 32 MiB is fine on desktop but hurts resume granularity on phones. [api.md](https://github.com/tus/tus-js-client/blob/main/docs/api.md)

**Server side** — open `.part` with `O_WRONLY|O_APPEND`; before each chunk `Stat()` and require `size == offset` (409 otherwise, return current offset so the client re-syncs). POSIX `O_APPEND` makes offset-positioning + write one atomic step, so even a duplicated chunk can't interleave. `MaxBytesReader(w, r.Body, chunkSize)` on the chunk endpoint. On finish: fsync, `os.Rename(part, final)` (atomic; same filesystem required; rename preserves mtime, so mtime = time of last byte written). Per-file vs parallel: one in-flight request per tab (see §4); serialise chunks of one file, queue files. [open(2)](https://man7.org/linux/man-pages/man2/open.2.html) · [renameio notes](https://pkg.go.dev/github.com/google/renameio/v2)

## 2. iOS Safari specifics

- **Background**: JS is suspended a few seconds after Safari goes to background (Apple engineer: "On iOS it is very intentional... you cannot control this"; forum measured ~7–8 s, others say 3 s). Resume on `visibilitychange === 'visible'` by HEAD-ing the offset. Old reports of in-flight XHR uploads dying with "network connection was lost" on iOS 12. [forum 777860](https://developer.apple.com/forums/thread/777860) · [frontendmasters](https://frontendmasters.com/courses/background-javascript/background-detection) · [forum 114624](https://developer.apple.com/forums/thread/114624)
- **Do not use FileReader for chunks on iOS**: a `readAsArrayBuffer(file.slice())` loop fails after exactly 60 s with `WebKitBlobResource error 1` (WebKit bug 228683, 2021; fix status **[unverified]**). `xhr.send(slice)` avoids reading into JS memory at all; upchunk saw RAM grow with file size when using FileReader. [forum 686192](https://developer.apple.com/forums/thread/686192) · [upchunk #89](https://github.com/muxinc/upchunk/issues/89)
- **Pickers**: `<input multiple>` → Photos multi-select works; "Browse" (Files) historically single-select **[unverified for iOS 18/26]**; camera `capture` keeps only the last shot. [forum 129845](https://developer.apple.com/forums/thread/129845) · [forum 826732](https://developer.apple.com/forums/thread/826732)
- **HEIC**: no `accept` → HEIC is transcoded to JPEG; `accept="image/jpeg,..."` → transcoded to the first listed type; Safari 17+ with `image/heic` in `accept` → JPEG/PNG are converted *to* HEIC as `tempImageXXXX.heic` with `lastModified` dropped. For a generic file-drop app: omit `accept` entirely. [forum 743049](https://developer.apple.com/forums/thread/743049) · [WebKit 292350](https://bugs.webkit.org/show_bug.cgi?id=292350) **[bug page blocked]**
- **Folder picker — correction to the brief**: Safari 18.4 (2025-03-31) release notes: "Improved `<input type="file" webkitdirectory>` support on iOS. (125457578)" — picks a folder from the Files app (not Photos albums). [Safari 18.4 notes](https://developer.apple.com/documentation/safari-release-notes/safari-18_4-release-notes)
- **Drag-and-drop folders**: `DataTransferItem.webkitGetAsEntry()` Chrome 13 / Edge 14 / Firefox 50 / Safari 11.1; `getAsFileSystemHandle()` Chrome/Edge 86 only. iOS has no file DnD into Safari from Files in practice. Use webkitGetAsEntry with recursive `readEntries()` (call until it returns an empty batch — Chrome returns ≤100 entries per call). **[web.dev page blocked]** [web.dev](https://web.dev/articles/files/drag-and-drop-directories)

| Capability | iOS Safari | Android Chrome | Desktop Chrome/Edge | Desktop Firefox | Desktop Safari |
|---|---|---|---|---|---|
| Multi-file picker | yes (Photos; Files single?) | yes | yes | yes | yes |
| `webkitdirectory` folder picker | 18.4+ (Files) | yes | yes | yes | yes |
| Drop files | no | no | yes | yes | yes |
| Drop folders (webkitGetAsEntry) | no | no | yes | yes | yes |
| Upload survives app switch | no (suspend ~3–8 s) | mostly | yes | yes | yes |
| `webkitRelativePath` on picked files | yes | yes | yes | yes | yes |

## 3. Download side

- **Content-Disposition**: Go's `mime.FormatMediaType("attachment", {"filename": name})` emits *only* `filename*=utf-8''%XX` (RFC 2231) when the value is non-ASCII, never a plain fallback, and returns "" on invalid input (open issue #43128 re `{}`). Build the header yourself: `attachment; filename="<ASCII fallback>"; filename*=UTF-8''<url.PathEscape>`. `filename*` works in Safari 6.2+; Safari (14.1 report) truncates very long header values, so keep the fallback short. [mediatype.go](https://github.com/golang/go/blob/master/src/mime/mediatype.go) · [go#43128](https://github.com/golang/go/issues/43128) · [forum 685138](https://developer.apple.com/forums/thread/685138) · [RFC 6266](https://www.rfc-editor.org/rfc/rfc6266)
- **ServeContent/ServeFile**: handle Range, `If-Match/If-Unmodified-Since/If-None-Match/If-Modified-Since/If-Range`, HEAD, and Content-Type sniffing; ServeFile rejects `..` and redirects `/index.html`. Prefer `ServeContent(w, r, name, modtime, f)` on an `*os.File` opened through `os.Root` and set `Content-Disposition` + `X-Content-Type-Options: nosniff` yourself. [ServeContent](https://pkg.go.dev/net/http#ServeContent)
- **Streaming zip**: `zip.Writer.CreateHeader` sets flag `0x8` and writes a trailing data descriptor (CRC/sizes after the data) so it streams without seeking; zip64 extras are written "if any size or offset REACHES OR EXCEEDS 4GiB"; UTF-8 flag `0x800` is set automatically for non-CP437 names; an extended timestamp is always emitted from `FileHeader.Modified`. Use `Method: zip.Store` (photos/video don't deflate; Deflate costs CPU on a small LXC). Write straight to the `ResponseWriter` (Go emits chunked encoding, no Content-Length), and call `http.Flusher.Flush()` after each file so progress is visible. [writer.go](https://github.com/golang/go/blob/master/src/archive/zip/writer.go) · [archive/zip](https://pkg.go.dev/archive/zip#Writer)
- **iOS downloads**: iOS 13+ Safari has a download manager; files land in Files → Downloads (iCloud Drive or "On My iPhone"), user-changeable in Settings → Safari → Downloads. Use a real link with `Content-Disposition: attachment` (the `download` attribute is unreliable on iOS); avoid blob/ObjectURL downloads (whole file in memory). No authoritative size ceiling found for direct downloads **[unverified]**. [cultofmac](https://www.cultofmac.com/how-to/safari-download-manager-ios-13) · [forum 91631](https://developer.apple.com/forums/thread/91631)

## 4. Server-sent events

- Spec authoring note: "Clients that support HTTP's per-server connection limitation might run into trouble when opening multiple pages from a site if each page has an EventSource to the same domain." Browsers cap HTTP/1.1 at ~6 connections per host; each EventSource holds one for its lifetime. **[spec page blocked]** [HTML spec](https://html.spec.whatwg.org/multipage/server-sent-events.html) · [textslashplain](https://textslashplain.com/2019/12/04/the-pitfalls-of-eventsource-over-http-1-1/)
- Reconnect rules: 500/502/503/504 and network errors → auto-reconnect (default delay a few seconds, server can set `retry: ms`; UAs may back off); **any other status, including 204, fails the connection permanently**. Lines starting with `:` are comments → heartbeat `: ping\n\n` every 15–30 s. [whatwg commit note](https://lists.whatwg.org/pipermail/commit-watchers-whatwg.org/2012/014313.html)
- Go pattern: `Content-Type: text/event-stream`, `Cache-Control: no-cache`, `Connection: keep-alive`; `fl := w.(http.Flusher)`; select on `r.Context().Done()`, a broadcast channel, and a `time.Ticker` for pings; `Server.WriteTimeout` must stay 0 or the stream dies. Go 1.24 can serve cleartext HTTP/2 (`Server.Protocols` + `UnencryptedHTTP2`, prior-knowledge only) but browsers never do h2c, so the 6-connection limit stands. [go#67816](https://github.com/golang/go/issues/67816)
- Mitigation: one EventSource per tab (close it on `pagehide`), **one in-flight chunk request per tab**, and fetch the list over the same SSE stream (first event = full snapshot) so nothing else competes. SharedWorker-based sharing is tempting but Chrome for Android only gained SharedWorker in Chrome 148 (Apr 2026) **[snippet]**; Safari iOS has it since 16. Budget: 1 SSE + 1 upload + 1 download + a few API calls = comfortably under 6 per tab; 3+ tabs on one phone is the only way to hit it. [caniuse](https://caniuse.com/sharedworkers)

## 5. Hardening (auth-less LAN)

- **Paths**: `filepath.IsLocal(p)` (Go 1.20) is lexical only — rejects absolute, empty, `..`-escaping and Windows reserved names; then open everything via `os.OpenRoot(dataDir)` (Go 1.24; "disallow any operations that would escape from the root either using relative path components or symlinks"). Go 1.25 added `Root.MkdirAll/RemoveAll/Rename/Chtimes/Truncate`, so the upload store can be built entirely on `*os.Root`. [IsLocal](https://pkg.go.dev/path/filepath#IsLocal) · [os.Root blog](https://go.dev/blog/osroot) · [os](https://pkg.go.dev/os#Root)
- **Names**: take `path.Base` of each client-supplied segment, NFC-normalise (`golang.org/x/text` would be a dep — skip; just strip), drop control chars `< 0x20` and `0x7f`, `/ \ : * ? " < > |`, trailing dots/spaces, and Windows reserved stems (`CON PRN AUX NUL COM1-9 LPT1-9`); cap at 255 bytes; empty → `unnamed`. Duplicates: `name (1).ext`, `(2)`... decided under a store mutex at *init* time and reserved by creating the `.part` with `O_CREATE|O_EXCL`. [MS naming rules](https://learn.microsoft.com/en-us/windows/win32/fileio/naming-a-file)
- **Disk guard**: `unix.Statfs(dir, &st)`; free = `uint64(st.Bavail) * uint64(st.Bsize)`; refuse init when `free - size < minFree` (default e.g. 1 GiB), re-check every N chunks. Only x/sys is needed. [x/sys/unix](https://pkg.go.dev/golang.org/x/sys/unix#Statfs)
- **TTL**: a goroutine every 10–15 min walks the root; delete files whose mtime is older than 7 days (mtime = last byte written, see §1), remove empty dirs, and delete `.part`/`.part.json` untouched for >24 h. No metadata index needed; the `.part.json` sidecar (name, size, offset, fingerprint, created) is only for resume and is removed on finish. Store original names on disk as-is so no index is needed for listing either.
- **http.Server**: `ReadHeaderTimeout: 10s`; leave `ReadTimeout`/`WriteTimeout` at 0 because, per the docs, ReadTimeout is "the maximum duration for reading the entire request, including the body" and WriteTimeout is "the maximum duration before timing out writes of the response... reset whenever a new request's header is read" — any non-zero value kills multi-GB uploads, zip streams and SSE. `IdleTimeout: 120s`, `MaxHeaderBytes: 1<<20`. For per-handler limits use `http.NewResponseController(w).SetReadDeadline/SetWriteDeadline` (Go 1.20) inside chunk handlers (e.g. 5 min per 16 MiB chunk). `MaxBytesReader` on JSON (64 KiB), text snippets (1 MiB) and chunk bodies. [Server](https://pkg.go.dev/net/http#Server) · [ResponseController](https://pkg.go.dev/net/http#ResponseController)
- **Listen**: `:8080` / `0.0.0.0:8080` is right for a LAN LXC; make `-addr` a flag so it can be bound to a VLAN IP. Set `Server.ErrorLog`, log client IP per upload, and reject `Host`-less or non-matching `Origin` on mutating requests only if you later add a reverse proxy (CORS is irrelevant same-origin).

## 6. Go specifics

- **Version**: upstream tags on 2026-10-07 include `go1.27.0`, `go1.27.1` and `go1.26.8` (go1.27rc1 was 2026-06-18; Go 1.26 shipped Feb 2026). Target `go 1.26` in go.mod (needs ≥1.25 for `Root.Rename`); CI on 1.27. Note this container only has go1.24.7 — set `toolchain go1.26.8` or install. [tags](https://github.com/golang/go/tags) · [Go 1.26 notes](https://go.dev/doc/go1.26)
- **Embedding**: `//go:embed web` on an `embed.FS`, `sub, _ := fs.Sub(webFS, "web")`, `http.FileServerFS(sub)` (Go 1.22) for `/`, `http.ServeFileFS` for `index.html`. Vendor `tus.min.js` into `web/` only if you adopt tus; otherwise zero JS deps. [embed](https://pkg.go.dev/embed) · [FileServerFS](https://pkg.go.dev/net/http#FileServerFS)
- **Zero third-party deps**: feasible — only `golang.org/x/sys/unix` (Statfs). tusd would add x/exp + a 30-module go.sum. Build: `CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -trimpath -ldflags "-s -w"` runs on Alpine without libc.
- **Layout**: `cmd/uped/main.go` (flags, embed, server start) · `internal/server` (mux, handlers: upload init/chunk/finish/abort, download, zip, text, SSE hub, static) · `internal/store` (os.Root-based store: reserve name, append chunk, finish, list, delete, sweep, statfs) · `internal/names` (sanitise/dedupe, pure, well-tested) · `web/` (index.html, app.js, style.css).

## 7. Web Share Target

Out of scope on plain HTTP: the Web Share (Target) API is "available only in secure contexts (HTTPS)" and `share_target` only works for an *installed* PWA (manifest + service worker, which also require HTTPS); Safari/iOS has never implemented `share_target` at all (WebKit bug 194593, open since 2019). [MDN](https://developer.mozilla.org/en-US/docs/Web/API/Web_Share_API) · [share_target](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Manifest/Reference/share_target) · [WebKit 194593](https://bugs.webkit.org/show_bug.cgi?id=194593)

## Recommended design

1. **Hand-roll a tus-shaped subset, not tus itself.** tus brings a 30-module go.sum and 65 KiB of JS for three verbs we can write in ~300 lines; keep the *semantics* (server-authoritative offset, 409 on mismatch, HEAD to resync) so a later swap to tusd is mechanical.
2. API: `POST /api/uploads {name, relPath, size, lastModified, fingerprint}` → `{id, offset}` (dedupes name, reserves `.part` + `.part.json`, checks Statfs); `HEAD /api/uploads/{id}` → `Upload-Offset`; `PUT /api/uploads/{id}?offset=N` body = one chunk (`MaxBytesReader` 16 MiB + 1; 409 + current offset on mismatch); `POST /api/uploads/{id}/finish` → fsync + `Root.Rename` to final; `DELETE /api/uploads/{id}` aborts. `POST /api/text {title, body}` writes `snippets/<ts>.txt`.
3. Client: XHR per chunk (`xhr.send(file.slice(off, off+16MiB))`), `upload.onprogress` → per-file bar = `off + e.loaded`; retry schedule `[0,1,3,5,10]s` then HEAD to resync offset; on `visibilitychange→visible` HEAD and continue; one chunk in flight per tab, files queued FIFO.
4. Fingerprint `name|size|lastModified|relPath` → `localStorage` map to `{id, offset}`; after reload, re-dropping the same file resumes (server HEAD is the truth). Stale `.part` >24 h is swept.
5. Folders: `webkitGetAsEntry` recursion on drop + `<input webkitdirectory>` button (works on iOS 18.4+, Android, desktop); `relPath` from `webkitRelativePath`/entry `fullPath`, each segment sanitised and `filepath.IsLocal`-checked, all I/O through `os.OpenRoot(dataDir)`.
6. No `accept` attribute (HEIC quirks); no FileReader anywhere; no fetch streaming.
7. Downloads: `GET /d/{path}` → `ServeContent` on a Root-opened file with hand-built `Content-Disposition` (ASCII fallback + `filename*`); `GET /zip?dir=…` → `archive/zip` with `zip.Store`, `Modified` set, flush per file, `Content-Disposition: attachment; filename="uped-<dir>-<date>.zip"`.
8. SSE: `GET /api/events` with a hub; first event `snapshot` (full list), then `added/removed/progress` deltas; `: ping` every 20 s; client closes it on `pagehide` and `EventSource` auto-reconnects on network loss.
9. Server: `ReadHeaderTimeout 10s`, `IdleTimeout 120s`, Read/WriteTimeout 0, per-chunk deadlines via `ResponseController`; sweeper goroutine (7-day mtime TTL + stale parts + empty dirs) every 15 min; Statfs guard at init and every 8 chunks.
10. Go 1.26 target, deps = `golang.org/x/sys` only, static `CGO_ENABLED=0` build, layout `cmd/uped`, `internal/{server,store,names}`, `web/`.

Could not verify (blocked sources): exact wording of the Chrome HTTP/1.x rejection; current status of WebKit bugs 228683/292350/319396; iOS Files "Browse" multi-select on iOS 18/26; any hard size limit on iOS direct downloads; caniuse SharedWorker table.
